# Kill Criteria

The architecture must be allowed to shrink.

## Kill or shrink full substrate runtime if

| Condition | Measurement | Action |
|---|---|---|
| strong retrieval/checkpoints/evals/ordinary skills match governed substrate | repeated-task benchmark | reduce to existing framework + ledger/claims |
| ledger + typed claims match promoted artifact arm | benchmark arms B/C vs D | stop at ledger/claims or governed skills |
| ordinary skills match promoted SkillArtifact | baseline skill arm vs governed skill arm | merge into ordinary skill governance |
| projection adds no measurable behavior change | A/B projection vs no projection | use static project instructions |
| activation bundle is static | same bundle in >80% of useful runs | replace dynamic activation with static domain pack |
| artifact model is metadata-only | manifests do not affect projection/eval/permissions/procedure | remove artifact layer |
| overhead exceeds saved debug/rework time | tokens/time/review burden vs saved work | shrink gate or artifact model |
| regression attribution fails | seeded bad artifact tests | forbid autonomous promotion; human-only governance |
| stale claims repeatedly survive invalidation | stale-state benchmark | stop promoting project claims until anchoring fixed |
| proposal queue bloats | low proposal survival, high review burden | reduce emitters/dreamers |
| provider outputs bypass gate | any provider-derived future influence without proposal/promotion | disable provider truth path |
| Hermes integration fights reuse | more effort bypassing Hermes than reusing it | move to clean runtime + imported primitives |
| OSS primitive already solves same layer | source-verified equivalent found | adopt existing framework instead |

## Reduction paths

If the stronger thesis fails, reduce to one of:

- requirements/evidence ledger;
- typed-claims system;
- governed memory only;
- governed skills only;
- static domain pack;
- benchmark/evaluation harness;
- adapter around existing framework.

## Non-negotiable guardrails

Even prototype runs must preserve:

1. kernel rules are not self-modified by ordinary runs;
2. providers do not define truth;
3. background workers emit proposals, not trusted writes;
4. every promoted claim/artifact has evidence and scope;
5. every active artifact/projection is logged;
6. elevated permissions remain separate from promotion;
7. bad artifacts can be demoted;
8. project claims can become stale;
9. no architecture expansion without benchmark evidence.
